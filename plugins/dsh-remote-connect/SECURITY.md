# Security

本文说明远程互联的威胁模型、已经做到的防护、以及明确没有做的事。最后一部分是
**已知限制**——请在使用公网连接前读它。

## 1. 威胁模型

| 场景 | 目标 |
| --- | --- |
| 同一局域网内的其他人 | 看不到同步内容，猜不到密码，不能借本机服务发起同步 |
| 公网上的扫描器 | 只能看到一个返回固定 JSON 的端点，无法枚举文件或触发同步 |
| 恶意网页（浏览器跨站） | 不能通过用户浏览器调用本机 8788 服务 |
| 传输链路被旁观 | 报文内容不可读，重放/篡改会被发现 |
| 接收端误覆盖 | 覆盖前有备份，整批可回滚 |
| 本机磁盘被读取 | **不在防护范围内**（见限制 1） |

## 2. 认证与密钥

```
password ──scrypt(N=2^14, r=8, p=1, 16B salt)──▶ K (32B, 仅内存)
clientNonce(16B) + serverNonce(16B)
        ──HKDF-SHA256(salt=cn||sn, info="dsh-link/session/v1")──▶ SK
proof = HMAC(K, "dsh-link/hello/v1|cn|sn|deviceId")
ready = HMAC(SK, "ready")
```

- 密码不参与任何网络报文；`/hello` 只返回 salt、KDF 参数、服务端 nonce 与挑战 id；
- 连接密码是 3 组 4 字符（`ABCD-EFGH-JKLM` 这种形状），字母表去掉了容易看错的 I / O / 0 / 1；
  输入时忽略空白与大小写；
- 挑战 60 秒过期并绑定来源 IP；验证失败累计 10 次锁定该 IP 10 分钟；
- 会话令牌 32 字节随机，12 小时过期；改密码会清空所有会话与主密钥缓存，并断开已有的出站对端连接；
- 每次请求签名：

```
HMAC-SK( METHOD | pathname | timestamp | nonce | sha256(body) )
```

时间偏移超过 5 分钟拒绝；nonce 在 10 分钟窗口内只能使用一次；
流式上传/下载的 body 摘要固定为字符串 `stream`，内容完整性由逐帧 GCM 认证保证。

## 3. 报文加密

- AES-256-GCM，每帧独立 12 字节 IV；
- AAD 为 `frame|<序号>`，乱序、插帧、截断都会解密失败；
- 帧格式：`[4B 长度][12B IV][密文][16B tag]`；
- JSON 响应使用同一密钥的 GCM 信封 `{e:1,iv,tag,ct}`；
- 传输层再套 gzip，压缩发生在加密之前。

## 4. 本地存储

| 文件 | 内容 | 权限 |
| --- | --- | --- |
| `<data>/config.json` | 设备身份、端口、**明文连接密码**、salt、同步策略 | 0600（Windows 依赖用户目录 ACL） |
| `<data>/peers.json` | 已配对设备的地址、密码（可选记住）、会话令牌与 SK | 0600 |
| `<data>/backups/<syncId>/` | 被覆盖文件的旧副本 | 继承目录权限 |
| `<data>/syncs/<syncId>/journal.json` | 本次同步的逐文件记录 | 0600 |

**为什么密码是明文？** 设置页需要把密码显示给用户，让他抄到另一台电脑。加密存储只能
防“读取文件的人”，却防不住“能运行 DSH 的人”，而后者本来就能调用设置页。与其做一层
虚假的加密，不如明确边界：`$DSH_HOME`（DSH 数据目录）应当被视为用户私有的敏感目录。

`peers.json` 里的 SK 只在对应服务端会话仍有效时有意义；改密码后服务端会话全部失效，
这些 SK 立即作废。

## 5. 默认不传的东西

- 目录：`node_modules/`、`.git/`、`.svn/`、`.hg/`、`__pycache__/`、`.cache/`、`.next/`、`.turbo/`、
  `.venv/`、`venv/`、`dist/`、`build/`、`coverage/`；
- 文件：`*.log`、`*.tmp`、`*.part`、`*.swp`、`*.map`、`*.lock`、`.DS_Store`、`Thumbs.db`；
- 凭据类：`.credentials.yaml`、`.dshw-api.json`、`model_config.json`、`.env*`、
  `*.pem/key/p12/pfx`、`id_rsa*`（含 ed25519 / ecdsa）、`.netrc`、`cookies*`；
- `storages/session_projcache/`；
- **远程互联自己的整个数据目录**（`config.json`、`peers.json`、`backups/`、`syncs/`）。

“包含凭据”开关存在，但默认关闭，且需要用户在同步页显式勾选。

## 6. 完整性、备份与回滚

- 每个文件在清单里带 SHA-256，接收端边写边算，不匹配立即删除临时文件并失败；
- 文件大小不符同样失败；
- 覆盖前复制到 `backups/<syncId>/`，新建文件记录为 `created`；
- 同尺寸且同 hash 的文件跳过，不产生写入；
- 整批完成后写 `journal.json`，支持一次性回滚；
- 备份默认保留 5 批，按时间修剪。

## 7. 公网暴露建议

**推荐**：SSH 反向隧道。链路自带加密与认证，不需要开放入站端口：

```bash
ssh -R 18788:127.0.0.1:8788 user@public-host
```

**可以**：Nginx/Caddy 反向代理 + 有效 TLS 证书。必须关闭响应缓冲
（`proxy_buffering off`）和请求缓冲（`proxy_request_buffering off`），否则流式同步会卡住。

**不要**：把 `8788/tcp` 以明文 HTTP 直接映射到公网。应用层虽然有 GCM，但
URL、时序、流量大小仍然暴露，而且没有证书校验，无法防中间人替换服务端。

## 8. 已知限制

1. **本地磁盘不是信任边界**：能读 `$DSH_HOME` 的人能拿到密码与会话密钥。请依赖操作系统账户隔离。
2. **没有 TLS 时无法防中间人**：应用层加密保护内容，但不认证服务端身份。公网请用隧道或 HTTPS。
3. **HTTPS 自签证书需要手动允许**：连接页的 `insecure` 选项会跳过证书校验，只应在可信网络使用。
4. **没有前向保密**：会话密钥由长期密码派生；密码泄露意味着历史抓包可被解密（如果攻击者同时拿到 salt 与 nonce）。
5. **同步是“最后写入者赢”**：不做内容级冲突合并；profile 依赖做了并集，其他文件是覆盖。
6. **不传输运行中的进程状态**：只同步磁盘文件，DSH 需要重启才能加载新插件。
7. **锁是按 IP 的**：NAT 后的多人共享同一公网 IP 时会一起被锁 10 分钟。
8. **依赖补齐会执行 npm 生命周期脚本**：点“补齐”后会运行 `npm install --omit=dev`，
   依赖包的 `preinstall/install/postinstall` 脚本将以你的用户权限执行。只和对端可信的机器同步；
   不想执行脚本时请手动在插件目录安装依赖。npm 不存在时补装会明确失败，不会静默跳过。

## 9. 报告问题

这是本地优先的社区插件。发现安全问题请附上复现步骤、DSH 版本、操作系统，
在项目仓库开 issue，或直接联系维护者。不要在生产环境验证破坏性利用。
