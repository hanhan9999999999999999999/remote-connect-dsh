# Changelog

所有值得注意的变更都记在这里。版本号遵循 [SemVer](https://semver.org/lang/zh-CN/)。

## 1.0.65 — 2026-11-15

### 修复

- **填错的端口被悄悄换成默认值**：两处填端口的地方以前都写 `Number(port) || 8788`。输入框里敲 `abc`（`Number` 得到 `NaN`）或者敲 `0`，都会被悄悄换成 8788，然后界面还说「已保存」——用户以为自己改成了 A，实际保存的是默认端口；连接表单里敲错端口，也会安静地去连默认端口，连不上的时候人完全摸不着头脑。
- 现在统一走 `parsePort(raw, { min, max })`：只认 1–5 位纯数字（`'8788.5'`、`'0x22b4'`、`'8e3'` 都不认，`' 9000 '` 会先 trim），监听端口要求 1024–65535、对端端口 1–65535；判不过就当场提示「端口要填 X–Y 之间的数字（现在是「你填的那个」）」并且一个请求都不发。从扫描结果里点进来的连接也走同一套校验（那里的端口是探测出来的数字，仍然核一遍）。

### 新增

- `test/client-port.mjs`（10 条断言）：把 `parsePort` 的函数体从 `client.js` 里抠出来真跑一遍，覆盖 `'8788'` / `' 9000 '` / 边界值 / `abc` / 空串 / `'0'` / 越界 / 小数 / 科学计数 / 十六进制 十四种输入；核对两个调用点都先判且判不过就 `return notify(...)`；最后扫一遍代码确认不再出现 `Number(port) || 默认值` 这种兜底（注释里提到旧写法不算）。
- 这个文件能接一个 `client.js` 路径参数：拿 `v1.0.64` 的版本跑同一个测试是 0 通过 6 失败（没有 `parsePort`、两处兜底都在）。

## 1.0.64 — 2026-11-15

### 修复

- **出错的提示和「已保存」一个腔调**：提示条以前一律 `aria-live="polite"`、4.2 秒消失。读屏软件会把错误排在当前正在朗读的内容之后——等它念到的时候，用户可能已经在点别的地方了；而错误本来是最需要立刻知道的那类。现在错误走 `assertive`、停 9 秒，普通成功仍 `polite`、4.2 秒。
- **连点两下，同一句话念两遍**：同一个提示连续出现两次时（比如反复点「断开」、扫描连着两次没结果），现在第二次把 `aria-live` 换成 `off`——对话框上照样看得见，只是不再念一遍。
- 空消息不再弹一个空条：`notify('')` 以前会撑出一个没有文字的气泡并把上一次的提示顶掉。

### 新增

- `test/toast-a11y.mjs`（11 项断言）：错误提示的停留时长、`assertive` 分支、重复内容走 `off`、空消息直接返回、`role="status"` 仍在、错误与警告条各有专用描边色、减少动效时提示条不做过渡。这个文件能接一个 `client.js` 路径参数：拿 `v1.0.63` 的版本跑同一个测试是 5 通过 6 失败，说明它抓的是这些行为而不是文件名。

## 1.0.63 — 2026-11-15

### 修复

- **本地打包失败时，上传会悬在那里**：`push()` 用 `packStream(entries).pipe(编码器)` 接上传流，而 `.pipe()` 不转发错误。打包途中某个文件读不到（被删了、被独占锁、权限变了）时，那条 gzip 只是带着 error 结束，编码器既不结束也不报错——于是这次上传一直挂着，直到 120 秒空闲超时，用户看到的是一句「对端迟迟没有响应」，而真正的原因在自己本机。这与 1.0.34 修的那个「源文件消失把进程抛死」是同一处毛病的另一面：那次让错误变成了事件，这次让事件真的有人接。
- 现在把 `pack` 的 `error` 转给编码器（包成 `READ_FAILED`），请求立刻失败并说清「读不到哪个文件」；失败路径照旧会向对端发一条 `DELETE /apply/<id>?reason=…`，不让对端挂着一个停在「接收中」的批次。

### 新增

- `test/peer-streams.mjs` 增加第 4 项：假对端的 `prepare` 正常、`PUT` 故意不回话，本地 entry 指向一个不存在的文件 → 断言 `push()` 在 3 秒内失败、错误里带「读不到」、且对端收到一条 `DELETE`。拿 `v1.0.62` 的 `host/peer.mjs` 跑同一个测试，这一项会红（另三项绿），说明它抓的正是这个缺陷。

## 1.0.62 — 2026-11-15

### 修复

- **面板快照有一块取不到，整页就是空白**：`status()` 以前把配置、服务状态、对端列表、最近批次、任务表串成一条链——任何一块抛错（配置损坏、网卡枚举失败、`peers.json` 坏了、`syncs/` 读不了）整份快照就是 500。而最需要看面板的时候恰恰是配置坏掉的时候，用户连「哪里坏了」都看不到，更没法动手去修。现在每块单独兜住：坏的那块降级成空值（`config` 用形状一致的空壳，其余空数组 / `{running:false}`），原因进 `degraded: [{section, code, error}]`，其余部分照常显示。
- **`init()` 自己失败会把状态接口整个打掉**：现在不抛，记一条 `section: 'init'` 的降级，并返回一份结构完整的空壳（`app` 里仍有版本与路径，能帮用户定位）。
- **降级了但没人知道**：界面顶部现在会渲染一条 `role="alert"` 的提示，写明「有 N 块信息没取到」并逐条列出 section 与原因——不是静默地显示一个看似正常的面板。

### 新增

- `test/status-degraded.mjs`（21 条断言）：正常时 `degraded` 为空数组且不写 warn（不能变成「永远在报警」）；配置坏掉时仍返回可用快照、`degraded` 带 `CONFIG_BROKEN` 与原因、`config` 是形状一致的空壳、其它块照常；服务状态坏掉时只有 `server` 进 `degraded`；对端/批次/任务同时坏时三块各自降级、服务与配置不受牵连；`init()` 失败时不抛且仍给空壳；界面确实渲染 `dlk-degraded` 且用的是 `role="alert"`。
- 这个文件能接一个模块路径参数：拿 `v1.0.61` 的 `host/service.mjs` 跑同一个测试是 4 通过 7 失败（旧版在配置坏掉、服务状态坏掉、三块同坏、`init` 失败时都直接抛出去）。

## 1.0.61 — 2026-11-15

### 修复

- **停手机通道时按过期端口去杀**：`stopBridge()` 以前只按 `runtime/port.json` 记的端口找进程。端口被占之后自动顺延、而记录没写成（1.0.51 修的那种情况）时，它一个 pid 都找不到，于是干等 12 秒报「进程仍在响应」——服务其实在另一个端口好好跑着，用户以为停不掉。现在先问记录端口，问不到就去监听表里认「命令行像 `server.mjs` 那个进程」，按**实际**端口找 pid 并杀，返回值里带 `port` 与 `recordedPort`。
- **停止失败会把暂停标记留在盘上**：以前先写 `paused.flag` 再杀进程，杀不掉就直接返回——于是服务还在跑，但下次 DSH 启动不会自动把它拉起来（面板显示「未运行」、实际在跑，或者反过来「明明开着，重启就没了」）。现在失败时会把标记撤掉，并在文案里说明撤没撤成功。
- **停止失败的提示只在卡片里悄悄红一行**：现在停止返回 `stopped:false` 时界面会当场弹一条警告，不用盯着卡片才发现服务没停。

### 新增

- `test/phone-stop.mjs`（14 条断言）：记录端口活着时按记录端口停、先写标记再杀；端口记录过期时按实际端口（8900）认进程并杀掉、且确实去认过一次；根本没在跑时直接报「已经停了」、不动进程也不写标记；写不进暂停标记时一个进程都不杀；杀不掉时报 `stopped:false`、撤掉暂停标记、文案里说明已撤销；客户端有 `stopped === false && error` 的提示分支。
- 这一轮没有拿旧文件跑反向验证：旧 `stopBridge()` 读的是**本机真实**端口记录，跑起来真会去杀本机正在用的桥接进程。改做静态核对——`v1.0.60` 的 `stopBridge()` 签名没有 `deps`、按 `listenerPid()` 无参调用（即记录端口）、也没有撤销暂停标记的代码，三条都对得上。

## 1.0.60 — 2026-11-15

### 修复（测试侧）

- `test/discovery-limits.mjs` 的灌包用例在 CI 的 `ubuntu-latest · node 22` 上红过：它让假设备一次回 300 条，断言「收回来正好 256 台」，而 loopback 的 UDP 缓冲区在 CI 上会丢包（实测只到 221 条）。这跟被测行为无关，是断言把「丢包」当成了「上限失效」。现在每轮灌 800 条、最多重扫 4 轮，直到 256 个名额真的被填满再断言；产品代码没有改动。

## 1.0.59 — 2026-11-15

### 修复

- **重放表能被人灌爆，还会越灌越慢**：nonce 那张表只在「超过 5000 条」时清一次过期的。可十分钟窗口内要真来了五千多个不同 nonce（一个已连上的对端就能做到），那次清理一条都删不掉——于是**每个请求都要把整张表从头扫一遍**，表还继续涨。现在重放表搬进 `host/guard.mjs` 的 `NonceStore`：硬上限 20000（`NONCE_MAX`），过期清理按秒摊销（不是每个请求都扫），到顶就挤掉最老的。
- **失败计数按来源地址无限堆**：`FailureTracker` 的 `entries` 以前没有上限，每个试过密码的来源都留一条永不清理的记录——扫一晚上就能把内存吃掉。现在上限 10000（`FAILURE_MAX`），先清「最后一次失败已经超过锁定期」的记录（顺带修掉「一年里零散失败十次也被锁」），再挤最老的，**正在锁着的来源不挤**。
- 会话与挑战的清理不再挂在「重放表超过 5000 条」这个条件上，改成 30 秒最多一次（`#maybePrune()`）；否则重放表搬家之后它们就没人清了。

### 内部

- `new LinkServer({ nonceMax, failureMax })` 可以覆盖两个上限（测试用）；`NonceStore.take(key, now)` 返回 `'ok'` / `'replay'`，`FailureTracker` 的 `blocked` / `register` / `clear` 语义不变。
- `test/security.mjs` 里那条「server 用上了 `NONCE_WINDOW_MS`」改成检查 `NonceStore` 的存在与实际调用点。

### 新增

- `test/guard-limits.mjs`（11 项断言）：同一 key 第二次算重放；到上限挤掉最老的（并断言被挤掉的那条以后能再用——这是上限换来的代价）；窗口过期清理；清理按时间摊销（`prunedAt` 不会被每个请求改写）；失败计数到上限时记一条警告；**被锁的来源不会被挤掉**；锁到期自己解开；默认值与导出的常量一致；真服务器上 `nonceMax` / `failureMax` 真的传到了两个结构里；同一个 nonce 发两次第二次是 401 `REPLAY`；灌 60 个请求后表仍不超过 `nonceMax`。
- 反向验证：拿 `v1.0.58` 那版 `host/guard.mjs` 跑同一个测试，7 条断言红（其中两条是「表停在上限」直接变成 9 条、4 条），说明它抓的是这些缺陷。

## 1.0.58 — 2026-11-15

### 修复

- **一轮探测能被灌满**：`scan()` 收回复没有数量上限，同网段谁都能往这个 UDP 端口灌包——一台机器在 1.5 秒里能塞进十几万条不同 id 的「回复」，全被当成设备存进 Map。现在收满 `SCAN_LIMITS.maxPeers`（256）之后多出来的直接丢掉，并记一条「另有 N 条超出上限被丢掉」的警告。
- **`timeoutMs` 没有下限也没有上限**：`NaN` 进 `setTimeout` 会变成 1 ms，扫描立刻返回空表（用户看到「一台都没有」）；传个特别大的值又能把界面拖住。现在 `scanWindow()` 把它收进 200–15000 ms，不是有限数就用默认 1500。
- **`extraHosts` 是外部输入**：以前原样并进广播目标，传一万个地址就发一万个包。现在 `sanitizeTargets()` 只认 IPv4 字面量（每段 ≤ 255）、去重、封顶 64 个。
- **套接字关掉之后再也不会自己恢复**：`start()` 在 UDP 套接字意外关闭后仍把 `this.socket` 留着，端口被别的程序抢走之后它永远认为「已经在跑」，`start()` 直接返回 false，局域网发现就此静默死掉。现在 `close` 会把 `this.socket` 放开并记一条 warn，下一次 `start()` 能真的重新绑上；绑定失败时同样会放开。
- 第二轮补发（450 ms 那次）现在会被清掉：扫描提前结束（超时更短、套接字报错）时不再往已关闭的 socket 上发，也不会把句柄多留半秒。

### 新增

- `test/discovery-limits.mjs`（15 条断言）：`scanWindow` 对 `NaN` / 非数字 / 过小 / 过大 / 正常值的行为；`sanitizeTargets` 的过滤、去重、封顶、非数组输入；真起一个「灌包设备」往扫描器回 300 条不同 id，断言收回来的不超过 256 台、日志里有一条「超出上限」、且灌包确实发生了（否则这条断言不算数）；`timeoutMs: NaN` 时按默认窗口等而不是立刻返回；套接字关掉后 `this.socket` 被放开、`start()` 还能重新绑上。
- 这个文件能接一个模块路径参数：拿 `v1.0.56` 那版 `host/discovery.mjs` 跑同一个测试，13 条断言全红（灌包那条实收 300 台、`NaN` 那条 3 ms 就返回、关掉之后再也起不来），证明它抓的是这些缺陷。

## 1.0.57 — 2026-11-15

### 修复

- **日志写不进去会把整个 DSH 带走**：`Logger` 用 `fs.createWriteStream` 写文件，却没给这条流挂 `error` 监听。日志目录不可写（盘满、目录被删、U 盘拔掉、权限变了）时 Node 会把异步的 `error` 升级成**未捕获异常**，进程直接退出——而那段代码的注释写着「logging must never throw」。现在 `error` 有监听：记下原因、关掉这条流、在内存 ring 里留一条「日志文件写不进去（原因），之后只留在内存里」的警告（只一条，不刷屏），日志本身继续进内存，`/logs` 照样能看。
- **写盘卡住时日志会把内存吃光**：`stream.write()` 的背压以前没人管，盘写得比产生的慢时缓冲区一直涨。现在按字节记账，积压超过 `maxPendingBytes`（默认 4 MB）就弃掉写不进去的行并计数，丢弃提示也只出一次。
- `close()` 现在真的关掉：置 `closed` 标记、断开 `stream`，之后写日志只进内存，不会把文件重新打开。`extra` 里有循环引用时也不再让序列化抛错（退回只带基本字段的一行）。

### 新增

- `test/logger.mjs`（15 条断言）：目录不存在时不抛、文件没被建出来、失败原因记下来了、警告只有一条、后续日志仍进内存；正常路径写成逐行 JSONL 且能解析回来；循环引用不抛；`close()` 之后文件大小不再变、日志仍进内存；背压上限生效且只提示一次；`warnOnce` 语义没被改坏。
- 这个文件能接一个模块路径参数，用来验证守卫本身：拿 `v1.0.55` 那版 `host/util.mjs` 跑同一个测试，进程会在第一条断言前就带着 `Unhandled 'error' event` 退出（exit 1），证明它抓的正是这个缺陷。

## 1.0.56 — 2026-11-15

### 修复

- **`Btn` 把调用方传的属性丢了**：它以前只解构自己认识的几个 prop，`onKeyDown`、`aria-live`、`data-*` 这些传进去**静默消失**。后果之一：本该给「危险操作」两段式确认按钮加的 Esc 撤防从来没生效过——键盘用户举起那只手之后只能干等 3.5 秒。现在 `Btn` 把剩下的属性原样摊到 `button` 上，`ConfirmBtn` 也真的支持 Esc 撤防了（武装状态下 `aria-live="polite"`，读屏器会念出「确认更换？」那句）。
- **键盘焦点看不见**：`.dlk-input` 写着 `outline: none` 却没有替代品，按钮 / 标签 / 开关 / 勾选 / 可点区块完全没有焦点样式——宿主页面一旦关掉全局 outline，键盘用户就不知道自己在哪。现在这六类控件统一给 `:focus-visible` 两像素描边（标签页是内描边，不撑开布局），并且系统开「减少动态效果」时 `.dlk-btn` / `.dlk-switch` / `.dlk-knob` / `.dlk-toast` 的过渡全部停掉。

### 测试

- `test/a11y.mjs` 增加两节：①六类控件必须有 `:focus-visible` 且带 `outline`，`.dlk-input` 关掉 outline 时必须另有兜底，`prefers-reduced-motion` 必须存在；②`Btn` 必须把 `...rest` 摊到 `button` 上、`ConfirmBtn` 必须有真的 Esc 撤防。这个文件现在也能接一个路径参数，用来验证「故意写坏的副本」会不会被抓（已用两份坏副本实测：删掉焦点规则、删掉 `...rest`，都会红）。
- `test/i18n-guard.mjs` 把 CSS 注释算作文风而不是漏翻（样式表也是一段字符串，之前会把 `/* … */` 里的中文当成写死的界面文字），但注释之外的 CSS 中文照样报错——用 `content:'请稍候'` 的坏副本实测过，会红。

## 1.0.55 — 2026-11-15

### 修复

- **批次建了却一个字节都没开始，就一直停在「接收中」**：两条这样的路——①拉取时对端在开下载流之前就失败（`prepare` 已经建好批次，本地没人收尾）；②推送时对端已经建好批次、我这边 `PUT` 直接断了。以前这两种都会在对端或本机留下一条永远不动的记录：`#trimStates` 只收 `done`/`failed`，界面挂着它、用户也没地方取消。现在 `Applier.discard(syncId, reason)` 把它落成 `failed` 并记下原因（重复调用回 `already`，不存在的回 `SYNC_UNKNOWN`），拉取两端各自收尾。
- **推送失败时对端的批次没人管**：`push()` 失败后会发一条 `DELETE /apply/<syncId>?reason=…` 让对方把这个批次收掉，服务端新增这条路由（幂等，批次不存在时 404 `SYNC_UNKNOWN`）。这一步是尽力而为——收尾失败不会盖住推送本身的错误。

## 1.0.10 — 2026-11-14

对着 `peer.mjs` 把「会话过期以后会怎样」走了一遍，走出两个真问题：一个会让人**只能手动重连**，一个让**超时被误报成网络错误**。

### 修复

- 会话过期后本地缓存不清：`ensureConnected()` 只看 `peer.session` 有没有，不看它是否过期；`#jsonFrom()` 拿到 401 也只抛错不清理。结果是进程一直拿着作废的 token 反复撞 401，用户必须手动断开重连才恢复。现在新增 `sessionUsable()`（留 30 秒余量），过期或收到 `UNAUTHORIZED` / `SESSION_EXPIRED` 时立刻把本地 session 置空，下一次操作自动重新握手。
