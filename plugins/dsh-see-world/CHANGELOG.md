# 更新记录

版本号遵守 [语义化版本](https://semver.org/lang/zh-CN/)：主版本改协议形状，次版本加能力，修订号只修缺陷。

## 0.3.2 — 2026-11-15

**修"采集在跑、画面是黑的"**

- **面板只显示一块黑，但亮度/帧率/帧数都在动**：采集和分析都好，坏在"把 30fps 推给浏览器"这一段。原来直接用 `<img src="/api/see-world/stream">` 让浏览器解 `multipart/x-mixed-replace`，而 Chromium 对这条流很挑：首段前面多一个 CRLF、或者它不喜欢当前的分段格式，就安静地什么都不显示（没有报错、没有 onError）。
  - 客户端改成**自己读流**：`fetch` + `ReadableStream` 一字节一字节喂进缓冲区，从字节里切出 `FFD8…FFD9` 的 JPEG，`createImageBitmap` 解出来画到 `<canvas>`。不再赌浏览器对 multipart 的容忍度；没有流式 fetch 或 `createImageBitmap` 的环境才退回 `<img>`。
  - 服务端也按规范改了：**第一段直接以 `--boundary` 开头**，不再前置 CRLF（有的解析器会把前置 CRLF 当成空段，于是整条流像"还没开始"）。
  - 流断了只在外面延迟 900ms 换 nonce 重连，不在组件内部自己重开（否则依赖一变就重跑，服务端一收流就成热循环）。
- `paneltest.mjs` 新增第 7 段：喂一条"半帧开头 + 两帧跨 read + 中间夹 multipart 噪音"的假流，断言切出 2 张图、画布尺寸跟着帧走、绘制次数对得上——这是黑屏那类问题的第一道防线。

## 0.3.1 — 2026-11-15

**给"面板点一下会怎样"补上自动化证据**

- 新增 `scripts/paneltest.mjs`：自带一套能 re-render 的迷你 React（useState / useEffect / useRef / useCallback / useMemo + 可控定时器 + window 监听），于是这些以前只能靠肉眼在 DSH 里看的行为，现在跑一条命令就有结论：打开面板会绑当前会话、点「开始」带上 sessionId、`running` 之后 `<img>` 换成 `/stream` 长连接（且地址里不带会话 id、按 `preview.fps` 请求）、按住标题栏拖动跟手且被右边界夹住、松手把 `{x,y,w}` 写进 localStorage、点「停止」、自动回报开着时关面板**不**停摄像头、关着时关面板顺手停。
- `package.json` 的 `verify` 加入 paneltest；README 自检节补一行说明。

## 0.3.0 — 2026-11-15

**让你能自己解决"它怎么不理我"**

- 设置页新增「**复制诊断信息**」：一键把配置、运行状态、设备列表拼成一段 JSON 放进剪贴板，贴给别人就能看明白现场（没有剪贴板权限时会给提示，不假装成功）。
- 面板底部新增「**改绑到当前会话**」：你切到别的会话、而面板还绑在原来那个时出现——显式改绑，不偷偷抢。
- 设置页那一项从「开启自动监控」改名「**预攒画面**」，并说清它和自动回报的关系（原来像两个重复开关）。
- `clienttest.mjs` 新增断言：遮罩层 `pointer-events:none` / 面板本体 `auto`（"不挡宿主操作"这条现在有证据）、诊断单是合法 JSON 且不带 `undefined`。

**修掉的缺陷**

- **面板「开始」之后从不启动"攒图"（monitor）**：`POST /control {action:'start'}` 只挂了回报循环，而回报循环读的是 `eye.pending`——没人往里放东西，于是「自动回报：开」却永远收不到消息。表现就是"面板开了、画面在动、它就是不理我"。现在 `start` 会先 `ensureMonitoring()` 再挂循环；`hosttest.mjs` 新增两条断言（`monitoring=true`、`reply.running/auto`）。
- `autoReply` 单独打开时也会自动挂上监控（不需要用户再去勾「预攒画面」）。

## 0.2.1 — 2026-11-15

**收尾打磨**

- 设置页顶部多一行实时状态：回报到哪个会话 · 自动回报开/关 · 间隔 · 运行状态，改完设置就能看见生效没有。
- 收起面板（× 或 Esc）时，如果自动回报是关着的，顺手放开摄像头——没有理由让一个不在看的窗口一直亮着灯；自动回报开着则继续值班。
- 关闭按钮的提示会随状态变（「收起面板，自动回报继续」/「收起面板并放开摄像头」）。
- `clienttest.mjs` 新增第 6 段：真点一次关闭按钮，验证"自动回报关着就调 stop"。
- 拖动的落点算法抽成纯函数 `clampBox` / `clampWidth`（模块通过 `__test` 暴露），`clienttest.mjs` 第 7 段覆盖 11 条：跟手、左上夹回、右下不出视口、底部留 64px、最小宽 360、不能宽过右边界。
- **「规矩只说一次」落到实处**：宿主维护 `toldSessions`，同一个会话一辈子只收一次规则块——关掉面板再开、绑走再绑回来都不重讲。`hosttest.mjs` 新增第 5b 段覆盖（讲过一次 → 重建 watcher 仍记得 → 新会话才讲）。

**修掉的缺陷**

- 设置页保存时漏发 `autoReply` / `replyIntervalSec` / `replyAttach` / `replyBudget` 四个字段——在设置页改回报选项等于白改。现在这四个字段一起提交。

## 0.2.0 — 2026-11-15

**自动回报：哪个会话开着面板，哪个会话就负责说话**

- 面板「开始」之后，宿主侧盯着画面，出现值得看的变化就自动往一个会话投消息（可带图），不用每次喊它看。
- 归属规则：工具的调用者 → 最近活动的会话 → 面板「回报到」手动改绑。改绑会让规矩重新说一次。
- 客户端读 `localStorage['dsh.sessions.current']`（shell 自己 persist 的当前会话）来判定"你正在看哪个会话"，点按钮那一刻就把回报目标绑过去。
- 新设置：`autoReply`、`replyIntervalSec`（3–600 秒）、`replyAttach`、`replyBudget`（1–200 次/段）。
- 「规矩只说一次」：第一条消息带规则块（不用调工具、只说一两句、没变化就说没变化），之后只发事实。

**面板不再定死**

- 按住标题栏拖动、右下角把手改宽，位置与宽度记在 localStorage。
- 浮层 `pointer-events:none`、面板自身 `auto`，所以不挡 DSH 的任何点击。

**修掉的缺陷**

- `watch()` 在刚开流、还一帧都没有时，返回空 sheet 却报成功，上层读 `sheet.png` 直接崩。现在如实返回「摄像头一帧都没送过来」+ 原因。
- 关流/卸载时一并关掉长连接预览与常驻编码器，避免留下僵尸子进程。

## 0.1.0 — 2026-11-15

**第一版：让 DSH 有眼睛**

- `see_world` 工具：`look` / `watch` / `peek` / `snapshot` / `devices` / `status` / `stop` / `help`。
- 一条 ffmpeg 双路输出（`pipe:1` 原生 MJPEG 给人看，`pipe:3` rgb24 给分析用），设备独占只开一次。
- 按"画面变了多少"挑帧、拼成一张带钟点和序号的图，装 4 帧和装 1 帧的 token 几乎一样。
- 亮度自动归一到中灰（过曝的摄像头画面不会变成一片白）。
- 设置页、输入框按钮、浮层面板三个入口。
- `scripts/selftest.mjs` / `hosttest.mjs` / `clienttest.mjs` 三套离线自检。
